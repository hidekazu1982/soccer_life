APK 作成手順書

文書SCS-OPS-01
版1.0（初版）
日付2026-11-26
関連SCS-SPEC-01、SCS-SPEC-02、SCS-SPEC-03。Claude プロジェクトの claude/apk-build-release-flow.md（同じ内容）
範囲APK の作り方、バージョンの決まり方、リリースノートと Google ドライブへの置き方、困ったときの対処

人が読む手順（第1〜6章）と、Claude が実行するときの手順（第7章）に分かれている。内容を変えるときは、Claude プロジェクトの claude/apk-build-release-flow.md と一緒に直す。

1. 全体の流れ

変更を入れる
  └ CHANGES_NEXT.md に変更メモを1行ずつ書く
APK を作る（3つの方法のどれか）
  ├ Unity が変更を取り込み、コンパイルを待つ
  ├ 変更メモからバージョンを自動で決める（新機能 +0.1.0 / 機能修正 +0.0.1）
  ├ ビルド → Builds\soccer_life.apk
  ├ ドライブへ APK をコピー（soccer_life_v{版}_{日時}.apk）
  ├ 14日を過ぎた古い APK をドライブから削除（最新版は残す）
  └ リリースノートを作ってドライブへコピー、変更メモを空に戻す

2. 前提条件

項目 内容
PC 起動していて、スリープしていない
Unity C:\project\soccer_life を開いている（Unity 6000.3.26f1、ビルド対象は Android）
Google ドライブ パソコン版 Google ドライブが動いていて、G:\マイドライブ が見える
Claude に頼む場合 Claude デスクトップアプリが開いていて、この会話が PC につながっている。C:\project\soccer_life フォルダが接続済み
注意 この PC の Unity は Auto Refresh がオフ。手で変更したスクリプトは Ctrl+R で取り込む（自動ビルドと依頼ビルドは自分で取り込む）

3. APK の作り方（3つの方法）

方法A：Claude に頼む（いちばん簡単）

  1. チャットで「APK作って」と送る
  2. Claude が依頼ファイルを置き、ビルドの完了まで見届けて、結果（ファイル名・バージョン・更新内容）を返す
  3. バージョンは聞かれない。変更メモから自動で決まる（2026-11-18 ユーザー指示）
  4. 音声通話からは PC を操作できないので、テキストのチャットで頼む

方法B：依頼ファイルを置く（自分で、画面操作なし）

  1. C:\project\soccer_life\Builds\ に、request-soccer_life.build という名前のテキストファイルを作る
  2. 中身に1語だけ書く
    • auto … 変更メモから自動で決める（ふつうはこれ）
    • minor … 新機能 +0.1.0
    • patch … 機能修正 +0.0.1
    • none … バージョンを上げない
  3. 5秒ほどで Unity がファイルを見つけて消し、ビルドが始まる（3〜11分）
  4. 結果は Builds\nightly-status.txt の最後の行で確認する（SUCCESS v0.x.y なら成功）

方法C：Unity の画面から手動で作る

  1. Unity のメニュー「File → Build Profiles」を開く（Ctrl+Shift+B）
  2. Android が Active になっていることを確かめ、「Build」を押す
  3. 保存先は C:\project\soccer_life\Builds\soccer_life.apk（上書きしてよい）
  4. 「APK のバージョン」ダイアログで、機能修正 / 新機能 / 上げない を選ぶ
  5. 終わると、ステータスバーに「Build completed with a result of 'Succeeded'」と出る

自動：毎朝 4:00〜4:30

  • Unity が開いていて、前回の APK のあとに Assets / Packages / ProjectSettings に変更がある日だけ、自動でビルドする
  • バージョンは変更メモから自動で決まる
  • PC が切れている、スリープしている、Unity が閉じている日は何もしない（4:30 を過ぎたらその日は飛ばす）
  • 止めたいときは、メニュー「SoccerClubSim → APKアップロード → 毎日4時に自動ビルド」のチェックを外す

4. 変更メモとバージョン

変更メモ（CHANGES_NEXT.md）

  • 場所：C:\project\soccer_life\CHANGES_NEXT.md（メニュー「SoccerClubSim → APKアップロード → 変更メモを開く」でも開ける）
  • 変更を入れたら「- 」で始まる1行で追記する（全スレッド共通ルール）
  • APK ができると、内容がリリースノートの【更新内容】に移り、ファイルは空のひな形に戻る

バージョンの決まり方

  • 形式：メジャー.マイナー.パッチ（開発中なのでメジャーは 0。リリース時に 1.0.0 へ手動で上げる）
  • 自動判定（変更メモの「- 」行を見る）
    • 「追加」「新設」「導入」「新機能」を含む行が1つでもある → 新機能 +0.1.0
    • ただし「台詞」「セリフ」「文言」「テキスト」「パターン」「翻訳」を含む行は数えない
    • それ以外、またはメモが空 → 機能修正 +0.0.1
  • 書き方のコツ：新しい機能・画面・イベントは「〜を追加」、直しは「〜を修正／変更／調整」
  • versionCode（Android の内部番号）＝ メジャー×1000000 ＋ マイナー×1000 ＋ パッチ（例：0.8.1 → 8001）
  • 自動ビルド・依頼ビルドが失敗したら、バージョンは元に戻る（手動ビルドの失敗は戻らない）

5. できるもの

場所 ファイル 内容
PC C:\project\soccer_life\Builds\soccer_life.apk 最新の APK（毎回上書き）
PC Builds\RELEASE_NOTES.txt リリースノート（新しい版が先頭）
PC Builds\nightly-status.txt 自動ビルド・依頼ビルドの記録（開始・判定理由・成功／失敗）
ドライブ G:\マイドライブ\game\soccer_life\APK\soccer_life_v{版}_{年月日_時分}.apk APK（版ごとに1ファイル）
ドライブ G:\マイドライブ\game\soccer_life\APK\RELEASE_NOTES.txt PC と同じリリースノート
  • リリースノートの1版ぶん：版と日時、versionCode、【更新内容】（変更メモ）、【変更ファイル】（前回の APK のあとに更新されたファイルを種類別に）
  • 古い APK の削除：APK をドライブに置くたびに、作ってから 14 日を過ぎた APK を消す。最新版は必ず残す。消したものは Google ドライブのゴミ箱に 30 日残る。日数は ApkDriveUploader.cs の KeepDays

6. 困ったとき

症状 原因 対処
依頼ファイルが消えずに残る Unity が閉じている／止まっている Unity Hub から soccer_life を開く。開けば依頼ファイルを見つけてビルドする
Unity を開くと「Enter Safe Mode?」が出る スクリプトにコンパイルエラーがある Safe Mode に入り Console のエラーを直す。直って Ctrl+R で取り込むと Safe Mode が自動で終わる
FAIL ... errors=N（記録の最後の行） コンパイルエラー、または取り込み前の変更 Console を開いて（Ctrl+Shift+C）エラーを見る。直したらもう一度依頼する（バージョンは戻っているので auto のままでよい）
「script class layout is incompatible」 変更したスクリプトが未コンパイルのままビルドした Ctrl+R で取り込んでから作り直す（依頼ビルドは自動で取り込むので通常は起きない）
手動ビルドでバージョンのダイアログが見えない 別のモニターや隠れた位置に出ている 依頼ファイル方式（方法B）を使う
Build Profiles が外したモニターに開いて押せない ウィンドウの位置が残っている 依頼ファイル方式（方法B）を使う
朝4時に作られていない PC のスリープ、Unity が閉じていた、変更がなかった nightly-status.txt に SKIP の記録があるか見る。記録がなければ Unity が動いていなかった
【更新内容】が「メモなし」 変更メモに書き忘れ リリースノートは手で書き足せる。新機能だった場合はバージョンが機能修正になっているので、次の依頼を minor にする

7. Claude が実行するときの手順

ユーザーに「APK作って」と頼まれたら、バージョンは聞かずに次の順で進める。

  1. 依頼ファイルを置く
    • 作業フォルダに毎回 新しいサブフォルダ を作り（例：/mnt/user-data/outputs/v{年月日}/）、中身 auto の request-soccer_life.build を書く
    • device_commit_files で C:\project\soccer_life\Builds\request-soccer_life.build に書き込む
    • 注意：同じパスのファイルを使い回すと、古い内容が送られることがあった（2026-11-09、11-13）。スクリプトを書き換えるときも新しいフォルダから送り、送ったあと device_stage_files で読み直して中身を確認する
  2. 受け付けを確認する（30〜45秒後）
    • Builds\nightly-status.txt を読み、最後の行が START 依頼ビルド（…） になっているか見る。判定（新機能／機能修正）と理由もここに出る
    • 依頼ファイルが残っていたら Unity が動いていない → コンピューター操作で Unity Hub から soccer_life を開く（Safe Mode が出たらエラーを直す。第6章）
  3. 完了を待つ（3〜11分）
    • nightly-status.txt の最後の行が SUCCESS v0.x.y になるまで待つ。FAIL なら Console でエラーを見る
  4. 結果を確かめる
    • Builds\RELEASE_NOTES.txt の先頭の版を読む
    • G:\マイドライブ\game\soccer_life\APK を一覧し、新しい APK と、削除された古い APK を確認する
  5. 報告する（🛠ケンジ）
    • ドライブの APK のファイル名とサイズ、リリースノートの場所
    • バージョン（前 → 後）と判定の理由
    • 更新内容の要約、変更ファイルの件数
    • 古い APK を削除したかどうか
    • 気になる点（メモが空なのにファイルが多く変わっている、など）

8. 関係するスクリプト（Assets/Editor）

ApkVersionBumper.cs ビルド直前にバージョンを上げる（手動ビルドではダイアログで選ぶ）
